# Direction method: the eight identity choices

For each choice, list two or three viable options, pick one, and record why. Options are starting points.

## 1. Color strategy
- Neutral plus one accent (most product UI): accent reserved for primary actions and key state.
- Duotone: two brand hues plus tinted neutrals; good for marketing and editorial.
- Multi-hue categorical: only when color encodes categories (charts, calendars); cap at 6-8 hues.
- Tint neutrals toward the brand hue slightly; pure gray beside a saturated accent looks disconnected.

## 2. Type pairing
- One family with a wide weight range is a legitimate choice. Pair only for a reason: display for personality plus text for reading plus mono for data or code.
- Match the x-height and proportions of paired fonts; contrast in structure (serif with sans) works better than two similar sans faces.

## 3. Shape language
- Pick one radius scale and apply it: square (0-2 px) reads technical or editorial; 4-8 px reads neutral; large radii or pills read friendly. Do not mix three radius styles on one screen.
- Match icon stroke weight to text weight.

## 4. Density
- Compact (data tools, 28-32 px rows), comfortable (default product UI), spacious (reading, marketing). Offer a density switch only when users live in the tool all day.

## 5. Layout rhythm
- Strict grid with consistent gutters for dashboards and forms; asymmetric or overlapping compositions for editorial and creative pages. Alignment still needs a visible logic.

## 6. Imagery and illustration
- Photography needs a consistent treatment (crop, color grade). Illustration needs one style, one stroke weight, one palette drawn from the tokens. If you cannot produce good imagery, use typography, diagrams and real data instead of stock filler.

## 7. Iconography
- One icon set per product. Label icons that are not universally understood. Do not use an icon as decoration where words would be clearer.

## 8. Motion language
- Define in one sentence ("quick and quiet", "slow and cinematic"), then choose durations and easings that match (see motion-design). Functional UI motion and expressive motion are different languages; do not mix them accidentally.

## Producing references without copying
Describe the quality you want from each reference in one line: "dense but legible like a railway timetable". Build from the quality, not from the reference's surface.
